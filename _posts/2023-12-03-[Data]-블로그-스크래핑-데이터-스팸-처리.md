## 블로그 스크래핑 데이터의 문제점

블로그 데이터를 스크래핑하다 보면 검색에 노출되도록 인기 키워드나 해시태그를 길게 나열한 글을 보게 된다. 이런 글까지 모으면 분석하려는 주제와 관계없는 키워드가 많이 섞일 수 있다.

특정 단어를 제외하는 방식으로 해결하기는 어렵다. 광고성 글에 쓰인 키워드도 일반적인 단어이기 때문에 정상적인 글까지 제외될 수 있다. 단어 자체보다 단어가 나열된 패턴을 찾아보려고 한다.

## 데이터 전처리 방안

### 연속적인 명사 단어 반복

광고성 글 중에는 검색 키워드를 명사 형태로 길게 나열하는 경우가 있다. 연속된 명사의 수를 세어 이런 글을 찾아보려고 한다. 다만 정상적인 상품 목록이나 기술 용어 목록도 명사가 이어질 수 있으므로 명사 나열만으로 스팸을 확정할 수는 없다.

예를 들어 '오늘 강아지 산책을 나갔는데 날씨가 너무 좋아서 행복했어요'를 KoNLPy의 Okt로 품사 태깅하면 아래처럼 확인할 수 있다. 출력은 작성 당시 예시이며 사전과 라이브러리 버전에 따라 달라질 수 있다.

```python
from konlpy.tag import Okt

okt = Okt()
text = "오늘 강아지 산책을 나갔는데 날씨가 너무 좋아서 행복했어요"
tagged = okt.pos(text)
print(tagged)
```

```text
[('오늘', 'Noun'), ('강아지', 'Noun'), ('산책', 'Noun'), ('을', 'Josa'), ('나갔는데', 'Verb'), ('날씨', 'Noun'), ('가', 'Josa'), ('너무', 'Adverb'), ('좋아서', 'Adjective'), ('행복했어요', 'Adjective')]
```

명사, 조사, 동사, 형용사, 부사 등 다양한 품사로 문장이 이루어진 것을 확인할 수 있다.

반면 키워드를 나열한 '강아지목줄 강아지사료 강아지인형 강아지수제간식 강아지껌 강아지유산균 강아지욕조 강아지울타리'를 같은 방식으로 분석하면 다음과 같다.

```python
from konlpy.tag import Okt

okt = Okt()
text = "강아지목줄 강아지사료 강아지인형 강아지수제간식 강아지껌 강아지유산균 강아지욕조 강아지울타리"
tagged = okt.pos(text)
print(tagged)
```

```text
[('강아지', 'Noun'), ('목줄', 'Noun'), ('강아지', 'Noun'), ('사료', 'Noun'), ('강아지', 'Noun'), ('인형', 'Noun'), ('강아지', 'Noun'), ('수제', 'Noun'), ('간식', 'Noun'), ('강아지', 'Noun'), ('껌', 'Noun'), ('강아지', 'Noun'), ('유산균', 'Noun'), ('강아지', 'Noun'), ('욕조', 'Noun'), ('강아지', 'Noun'), ('울타리', 'Noun')]
```

대부분 명사가 이어진다. 여기서 세는 것은 띄어쓰기로 나눈 단어 수가 아니라 Okt가 나눈 형태소 중 `Noun` 태그가 연속되는 수이다. 중간에 조사나 동사처럼 다른 품사가 나오면 다시 0부터 센다.

## 연속 명사 수로 후보 찾기

여기서는 연속 명사가 30개 이상인 글을 필터링 후보로 본다. 30은 예제의 기준값이지 모든 블로그 데이터에서 검증된 값은 아니다. 위의 짧은 키워드 예시는 30개 미만이므로 이 함수로 제거되지 않는다.

```python
from konlpy.tag import Okt

# 형태소 분석기는 글마다 새로 만들지 않고 재사용한다.
okt = Okt()

def max_consecutive_nouns(tagged):
    max_consecutive_nouns = 0
    current_consecutive_nouns = 0

    for word, pos in tagged:
        if pos == 'Noun':
            current_consecutive_nouns += 1
            max_consecutive_nouns = max(max_consecutive_nouns, current_consecutive_nouns)
        else:
            current_consecutive_nouns = 0

    return max_consecutive_nouns

def remove_text_with_consecutive_nouns(text, threshold=30):
    tagged = okt.pos(text)
    return None if max_consecutive_nouns(tagged) >= threshold else text
```

`max_consecutive_nouns()`는 글에서 명사가 가장 길게 이어진 구간의 길이를 반환한다. `remove_text_with_consecutive_nouns()`는 그 값이 기준 이상이면 `None`을 반환한다. 형태소 분석기는 글마다 새로 만들지 않고 재사용한다.

## 바로 삭제해도 될까?

상품 목록이나 여행 준비물처럼 정상적인 글에도 명사가 길게 이어질 수 있다. 반대로 광고성 글 사이에 조사를 넣으면 이 기준을 통과할 수도 있다. 연속 명사 수만으로 광고 여부를 판별하기는 어렵다.

실제 파이프라인에서는 원문을 바로 없애기보다 후보 여부와 연속 명사 수를 함께 남기는 방법이 있다. 아래 함수는 앞서 만든 `okt`와 `max_consecutive_nouns()`를 사용한다.

```python
def inspect_text(text, threshold=30):
    noun_count = max_consecutive_nouns(okt.pos(text))
    return {
        "text": text,
        "max_consecutive_nouns": noun_count,
        "is_spam_candidate": noun_count >= threshold,
    }
```

이 결과에서 후보로 분류된 글과 통과한 글을 모두 일부씩 확인한다. 정상 글이 자주 걸리면 기준을 조정하고 광고성 글이 많이 남으면 다른 패턴을 함께 검토한다. 단순히 제거한 글 수가 많다는 이유로 필터가 잘 동작한다고 판단해서는 안 된다.

## 마무리

연속 명사 수는 키워드를 길게 나열한 글을 찾는 간단한 기준으로 사용할 수 있다. 바로 삭제하기보다 원문과 판정 이유를 함께 남겨 정상 글이 얼마나 제외되는지 확인하는 편이 좋다. 실제로 적용할 임계값도 수집한 데이터에서 오탐과 누락을 비교해 정해야 한다.
