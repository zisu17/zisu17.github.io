## 도커(Docker)

애플리케이션을 다른 서버에서 실행하려면 코드뿐 아니라 라이브러리와 실행에 필요한 파일도 준비해야 한다. Docker는 이 실행 환경을 이미지로 묶고 컨테이너로 실행할 수 있게 해준다.

### 이미지와 컨테이너

**이미지**는 애플리케이션 코드와 라이브러리, 실행에 필요한 파일을 묶은 결과물이다. **컨테이너**는 그 이미지를 바탕으로 만드는 실행 단위이다. 컨테이너를 시작하면 그 안에서 지정한 프로세스가 실행된다.

예를 들어 Nginx 이미지 하나로 웹 서버 컨테이너를 여러 개 만들 수 있다. 같은 이미지로 시작하더라도 각 컨테이너의 실행 상태와 생성한 파일은 별도로 관리된다.

컨테이너는 호스트의 커널을 공유한다. 실행 환경을 맞추는 데 도움이 되지만 OS와 CPU 아키텍처까지 무관해지는 것은 아니다. Linux 컨테이너를 macOS나 Windows에서 실행할 때는 Docker Desktop 등이 제공하는 Linux 가상 환경을 사용한다.

## Docker 명령은 어디에서 실행될까?

터미널에서 `docker run`을 입력하는 도구는 Docker Client이고 실제로 컨테이너를 만들고 실행하는 쪽은 Docker Daemon이다.

### 도커 서버(Docker Server)

Docker Daemon은 이미지와 컨테이너, 네트워크, 볼륨을 관리하는 프로세스이다. 이미지를 가져오고 컨테이너를 생성하거나 중지하는 작업을 처리한다.

### 도커 클라이언트(Docker Client)

Docker Client는 사용자가 입력한 명령을 Daemon에 전달한다. Client와 Daemon은 같은 컴퓨터에 있을 수도 있고 원격으로 연결할 수도 있다.

```text
터미널의 docker 명령 → Docker Daemon → 이미지·컨테이너 관리
```

## 기본 명령어

- `pull`: 레지스트리에서 이미지를 가져온다.

    ```bash
    docker pull <저장소명/이미지명:태그>
    ```

- `push`: 로컬 이미지를 레지스트리에 올린다. 아래는 Docker Hub에 올리는 예시이다.

    ```bash
    docker image tag my-app:latest YOUR_DOCKER_USERNAME/my-app:1.0
    docker login
    docker push YOUR_DOCKER_USERNAME/my-app:1.0
    ```

- `commit`: 컨테이너의 파일 변경과 설정을 새로운 이미지로 저장한다. 볼륨의 데이터는 포함하지 않는다. 빌드 과정을 다시 실행할 수 있도록 남기려면 Dockerfile을 사용하는 편이 좋다.

    ```bash
    docker commit <컨테이너이름 or 컨테이너id > <저장할 이미지명>
    ```

- `run`: 이미지로 새 컨테이너를 만들고 실행한다. `-d`는 백그라운드 실행이고 `-p`는 호스트 포트와 컨테이너 포트를 연결하는 옵션이다.

    ```bash
    docker run -d --name <컨테이너 이름> -p <로컬포트:도커포트> <이미지이름 or 이미지id>
    ```

- `start`: 중지된 컨테이너를 다시 시작한다.

    ```bash
    docker start <컨테이너이름 or 컨테이너id >
    ```

- `restart`: 컨테이너를 중지한 뒤 다시 시작한다. 호스트 OS를 재부팅하거나 새 이미지로 교체하는 명령은 아니다.

    ```bash
    docker restart <컨테이너이름 or 컨테이너id>
    ```

- `stop`: 실행 중인 컨테이너를 중지한다.

    ```bash
    docker stop <컨테이너이름 or 컨테이너id >
    ```

- `exec`: 실행 중인 컨테이너 안에서 명령을 실행한다. 아래 예제는 `-it`로 대화형 터미널을 연결해 Bash를 실행한다.

    ```bash
    docker exec -it <container_id> bash
    ```

- `ps`: 실행 중인 컨테이너를 확인한다. `-a`를 붙이면 중지된 컨테이너도 표시한다.

    ```bash
    docker ps
    docker ps -a
    ```

- `rm`: 컨테이너를 삭제한다. 삭제할 컨테이너를 확인한 뒤 실행한다.

    ```bash
    docker rm <컨테이너이름 or 컨테이너id >
    ```

- `images`: 로컬에 있는 이미지를 확인한다.

    ```bash
    docker images
    ```

- `rmi`: 로컬 이미지를 삭제한다. 컨테이너를 삭제하는 명령과는 다르다.

    ```bash
    docker rmi <이미지명 or 이미지id >
    ```

- `image tag`: 같은 이미지를 가리키는 새 이름과 태그를 추가한다. 기존 태그를 지우거나 이미지 내용을 바꾸지는 않는다.

    ```bash
    docker image tag <기존 이미지명>:<기존 태그명> <새 이미지명>:<새 태그명>
    ```

명령의 `<...>` 부분은 자신의 값으로 바꾸고 꺾쇠는 제외한다. `YOUR_DOCKER_USERNAME`은 자신의 Docker Hub 계정명이다. `exec` 예제의 `bash`는 이미지에 Bash가 설치되어 있어야 사용할 수 있다. 없다면 `sh` 등 제공되는 셸을 확인한다.

## 컨테이너 실행과 포트 연결

다음 명령은 Nginx 컨테이너를 만들고 호스트의 8080 포트를 컨테이너의 80 포트에 연결한다.

```bash
docker run -d --name web -p 127.0.0.1:8080:80 nginx:stable
docker ps
```

브라우저에서 `http://localhost:8080`으로 접속하면 된다. 앞의 `127.0.0.1`은 이 컴퓨터에서만 접근하도록 제한한 주소이다. 이를 빼고 `8080:80`으로 지정하면 기본적으로 호스트의 모든 인터페이스에 포트가 공개되므로 외부 접근 범위도 확인해야 한다.

`docker stop web`으로 중지한 컨테이너는 `docker start web`으로 다시 실행할 수 있다. 같은 이름으로 `docker run`을 반복하면 기존 컨테이너가 남아 있어 이름 충돌이 발생한다.

## 컨테이너를 지워도 데이터를 남기려면

컨테이너를 중지하는 것과 삭제하는 것은 다르다. 중지한 컨테이너의 파일은 남아 있지만 컨테이너를 삭제하면 쓰기 계층에 저장한 파일도 사라진다. DB 데이터처럼 컨테이너를 교체해도 남아야 하는 파일은 볼륨에 보관한다.

아래는 `app-data`라는 이름의 볼륨에 파일을 쓰고 새 컨테이너에서 다시 읽는 예시이다.

```bash
docker volume create app-data

docker run --rm --mount type=volume,src=app-data,dst=/data \
  alpine:3 sh -c 'echo hello > /data/message.txt'

docker run --rm --mount type=volume,src=app-data,dst=/data \
  alpine:3 cat /data/message.txt
```

두 명령은 서로 다른 컨테이너를 만들지만 같은 볼륨을 사용한다. 첫 컨테이너가 종료되어 삭제된 뒤에도 두 번째 컨테이너에서 `hello`를 읽을 수 있다. 다만 볼륨 자체를 지우면 데이터도 없어지므로 별도 백업까지 대신해주는 것은 아니다.

## 마무리

이미지와 컨테이너를 구분하면 명령어도 이해하기 쉽다. `run`은 새 컨테이너를 만들고 `start`는 기존 컨테이너를 다시 시작한다. 컨테이너를 교체해도 남아야 하는 데이터는 볼륨 등으로 분리해 보관한다.
