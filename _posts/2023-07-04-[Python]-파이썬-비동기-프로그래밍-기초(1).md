## 비동기 프로그래밍이란?

API를 여러 번 호출할 때 앞선 응답을 받을 때까지 다음 요청을 보내지 않으면 대기 시간이 쌓인다. 서로 의존하지 않는 요청이라면 먼저 보낸 요청의 응답을 기다리는 동안 다른 요청도 보낼 수 있다.

**비동기 프로그래밍**은 이렇게 작업이 완료되기를 기다리는 동안 다른 작업을 진행할 수 있도록 구성하는 방식이다. 실행 순서가 무작위로 바뀐다는 뜻은 아니다.

파이썬에서는 표준 라이브러리인 `asyncio`를 사용할 수 있다. 아래 예제에서는 하나의 스레드에서 이벤트 루프가 여러 코루틴을 번갈아 실행한다. 이벤트 루프는 실행할 수 있는 작업을 골라 진행하는 역할을 한다.

중요한 것은 대기하는 코드도 비동기를 지원해야 한다는 점이다. `async def` 안에 일반적인 파일 읽기나 `requests.get()` 같은 블로킹 함수를 넣는다고 자동으로 비동기로 바뀌지는 않는다.

![비동기 프로그래밍 개념도](https://github.com/zisu17/zisu17.github.io/assets/108858121/c9a649e1-63ec-4a27-8783-0228ab4455ec)

## async와 await 사용하기

먼저 1초를 기다린 뒤 다음 문장을 출력하는 예제이다.

```python
import asyncio

async def main():
    print('Hello')
    await asyncio.sleep(1)
    print('World')

asyncio.run(main())
```

`async def`로 선언한 `main()`을 호출하면 코루틴 객체가 만들어진다. 코루틴은 중간에 실행을 멈추고 나중에 이어갈 수 있는 작업이라고 생각하면 된다. `asyncio.run()`이 이벤트 루프를 시작해 이 코루틴을 실행한다.

`await asyncio.sleep(1)`에서는 현재 코루틴을 잠시 멈추고 이벤트 루프에 실행 기회를 넘긴다. 약 1초 뒤 다시 실행할 수 있게 되면 `World`를 출력한다.

![Hello와 World 실행 결과](https://github.com/zisu17/zisu17.github.io/assets/108858121/efa11a6a-2c27-4ecc-95bb-d082bbc1d713)

결과만 보면 `time.sleep(1)`을 사용해도 같아 보인다. 둘 다 `Hello`를 출력한 뒤 약 1초 후에 `World`를 출력하기 때문이다.

### time.sleep과 asyncio.sleep의 차이

`time.sleep(1)`은 호출한 스레드를 1초 동안 대기시킨다. CPU 전체를 멈추는 것은 아니므로 다른 스레드나 프로세스는 실행될 수 있다. 다만 이벤트 루프가 실행 중인 스레드에서 호출하면 그 루프의 다른 코루틴도 함께 기다리게 된다.

반면 `await asyncio.sleep(1)`은 현재 코루틴만 대기시킨다. 이벤트 루프는 다른 코루틴을 실행할 수 있다. 첫 예제에는 다른 작업이 없어서 이 차이가 잘 보이지 않는다.

## 여러 작업의 대기 시간 겹치기

이번에는 1초를 기다리는 작업을 다섯 번 실행해보려고 한다. 먼저 `time.sleep()`으로 순서대로 실행한다.

```python
import time

def job(number):
    print(f'Starting job {number}')
    time.sleep(1)
    print(f'Finishing job {number}')

start = time.time()
for i in range(5):
    job(i)
end = time.time()
print("전체 소요시간 : ", end - start)
```

작업 하나가 끝나야 다음 작업을 시작하므로 전체 실행 시간은 약 5초이다.

![순차 대기 예제 실행 결과](https://github.com/zisu17/zisu17.github.io/assets/108858121/81745d8a-2233-475a-8a30-d2b91a2567d9)

서로 독립적인 대기 작업이라면 기다리는 시간을 겹칠 수 있다. 같은 예제를 `asyncio`로 작성한다.

```python
import asyncio
import time

async def job(number):
    print(f'Starting job {number}')
    await asyncio.sleep(1)
    print(f'Finishing job {number}')

async def main():
    tasks = [job(i) for i in range(5)]
    await asyncio.gather(*tasks)

start = time.time()
asyncio.run(main())
end = time.time()
print("전체 소요시간 : ", end - start)
```

`job(i)`를 호출한 것만으로 작업이 시작되지는 않는다. 여기서는 `asyncio.gather()`가 다섯 코루틴을 실행 대상으로 등록한다. `main()`은 모든 결과를 기다리지만 그동안 이벤트 루프는 각 `job()`을 실행할 수 있다.

각 작업의 1초 대기가 겹치므로 전체 실행 시간은 약 1초이다. 계산량이 줄어든 것이 아니라 대기 시간을 함께 사용한 결과다.

![동시 대기 예제 실행 결과](https://github.com/zisu17/zisu17.github.io/assets/108858121/0b06b540-6de1-45d2-9a6e-e12d8d0f448b)

### await만 붙이면 동시에 실행될까?

앞선 예제의 `main()`만 아래처럼 바꾸면 앞선 작업이 끝난 뒤 다음 작업을 시작한다. `await`를 사용했어도 전체 시간은 약 5초가 걸린다.

```python
async def main():
    for i in range(5):
        await job(i)
```

각 `job()`이 기다리는 동안 이벤트 루프는 다른 작업을 실행할 수 있다. 하지만 이 반복문은 다음 `job()`을 아직 시작하지 않았다. 여러 작업의 대기 시간을 겹치려면 앞선 예제처럼 `gather()` 등으로 함께 실행할 작업을 등록해야 한다.

## 마무리

`await`는 기다림 자체를 없애는 문법이 아니다. 현재 코루틴이 결과를 기다리는 동안 이벤트 루프가 다른 작업을 실행할 수 있게 한다. 실제 API 호출에서도 비동기를 지원하는 클라이언트를 사용해야 같은 방식으로 대기 시간을 겹칠 수 있다.

CPU 계산만 오래 하는 코드를 넣으면 이벤트 루프가 다른 작업으로 넘어갈 기회를 얻지 못할 수 있다. 비동기를 적용하기 전에 어떤 부분에서 시간을 쓰는지부터 구분해야 한다.
