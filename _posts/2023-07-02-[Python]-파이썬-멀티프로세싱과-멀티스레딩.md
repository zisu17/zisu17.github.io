## 병렬처리(Parallel Processing)

하나의 작업을 여러 부분으로 나누어 동시에 실행하면 전체 시간을 줄일 수 있다. 예를 들어 1부터 100만까지 소수를 찾는다면 범위를 네 구간으로 나누어 계산하는 방식이다.

파이썬에서는 멀티프로세싱과 멀티스레딩으로 작업을 나눌 수 있다. 다만 둘 다 작업을 여러 개 실행한다는 이유로 같은 성능이 나오는 것은 아니다. 계산이 오래 걸리는지와 외부 응답을 기다리는 시간이 긴지에 따라 적합한 방식이 달라진다.

## 멀티프로세싱(Multiprocessing)과 멀티스레딩(Multithreading)

**멀티프로세싱**은 여러 개의 독립적인 프로세스에 작업을 나누는 방식이다. 여러 CPU 코어가 있다면 각 프로세스가 서로 다른 코어에서 계산할 수 있다.

프로세스마다 메모리 공간이 분리되어 있어 한 프로세스의 변수가 다른 프로세스에 그대로 공유되지는 않는다. 프로세스를 만드는 비용과 데이터를 전달하는 비용도 든다. 작은 작업까지 잘게 나누면 이 비용 때문에 오히려 느려질 수 있다.

**멀티스레딩**은 하나의 프로세스 안에서 여러 스레드에 작업을 나누는 방식이다. 스레드끼리는 메모리를 공유하므로 같은 데이터에 접근하기 쉽다. 대신 같은 값을 동시에 수정할 때는 락 같은 동기화가 필요하다.

스레드를 여러 개 만든다고 항상 여러 코어에서 파이썬 코드가 병렬로 실행되는 것은 아니다. 여기서 GIL을 구분해야 한다.

## 파이썬에서의 멀티프로세싱과 멀티스레딩

파이썬에서는 `multiprocessing`과 `threading` 모듈을 사용할 수 있다. 스레드 풀은 `concurrent.futures.ThreadPoolExecutor`로도 구성할 수 있다.

아래 예제는 GIL이 활성화된 일반적인 **CPython**을 기준으로 한다. **GIL**(Global Interpreter Lock)은 같은 인터프리터에서 한 번에 하나의 스레드만 파이썬 바이트코드를 실행하도록 한다. 그래서 파이썬 코드로 계산만 하는 CPU 바운드 작업은 스레드를 늘려도 빨라지기 어렵다.

파일이나 네트워크 I/O를 기다릴 때는 GIL이 해제되므로 다른 스레드가 작업할 수 있다. 예를 들어 여러 API를 호출한다면 한 스레드가 응답을 기다리는 동안 다른 스레드가 다음 API를 호출할 수 있다.

멀티프로세싱은 프로세스마다 별도의 인터프리터와 GIL을 사용한다. 계산을 여러 코어에 나눌 수 있으므로 아래의 소수 찾기처럼 파이썬 연산이 많은 작업에 적합하다.

Python 3.13부터는 GIL을 비활성화할 수 있는 free-threaded 빌드도 제공된다. 또 일부 확장 라이브러리는 계산 중 GIL을 해제한다. 이런 경우는 위 설명과 구분해야 한다.

### 파이썬 멀티프로세싱 예제

소수를 찾는 함수를 단일 프로세스와 여러 프로세스에서 실행해 시간을 비교해보려고 한다. 아래 코드는 `function.py`에 저장한다.

`is_prime()`은 소수를 판별하고 `find_primes()`는 `start`부터 `end`까지의 소수를 찾는다. 풀에 넘길 함수도 이 파일에 두어 자식 프로세스에서 불러올 수 있게 한다.

```python
# 소수 판별 함수
def is_prime(n):
    if n < 2:
        return False
    for i in range(2, int(n**0.5)+1):
        if n % i == 0:
            return False
    return True

# 소수 찾는 함수
def find_primes(start, end):
    primes = []
    for n in range(start, end+1):
        if is_prime(n):
            primes.append(n)
    return primes

def find_primes_wrapper(args):
    return find_primes(*args)
```

다음 코드는 같은 폴더의 별도 파일에 저장해 실행한다. 1부터 100만까지 한 번에 계산한 뒤 네 구간으로 나누어 계산한다.

```python
from multiprocessing import Pool
import time
from function import find_primes, find_primes_wrapper

if __name__ == "__main__":
    start_time = time.time()
    find_primes(1, 1000000)  # 1에서 1000000까지의 소수 찾기
    print(f'싱글 프로세싱 작업 소요 시간 : {time.time() - start_time}')

    start_time = time.time()
    with Pool(processes=4) as p:
        results = p.map(find_primes_wrapper, [(1, 250000), (250001, 500000), (500001, 750000), (750001, 1000000)])
    print(f'멀티 프로세싱 작업 소요 시간 : {time.time() - start_time}')
```

`if __name__ == "__main__":` 아래에 실행 코드를 둔 것은 자식 프로세스가 모듈을 불러올 때 풀을 다시 만들지 않게 하기 위해서다. 특히 새 인터프리터로 시작하는 `spawn` 방식에서 필요한 구분이다.

2023년 실습에서는 단일 프로세스가 2.57초, 멀티프로세싱이 0.94초로 약 2.7배 빨랐다. CPU 코어 수와 프로세스 시작 방식, 작업 크기에 따라 시간은 달라진다.

### 파이썬 멀티스레딩 예제

이번에는 같은 함수를 `ThreadPoolExecutor`로 최대 4개의 스레드에 나눈다. 작업 구간은 멀티프로세싱 예제와 같다.

```python
import time
from concurrent.futures import ThreadPoolExecutor
from function import find_primes

if __name__ == "__main__":
    start_time = time.time()
    find_primes(1, 1000000)  # 1에서 1000000까지의 소수 찾기
    print(f'싱글 스레딩 작업 소요 시간 : {time.time() - start_time}')

    start_time = time.time()
    with ThreadPoolExecutor(max_workers=4) as executor:
        results = list(executor.map(find_primes, [1, 250001, 500001, 750001], [250000, 500000, 750000, 1000000]))
    print(f'멀티 스레딩 작업 소요 시간 : {time.time() - start_time}')
```

당시 결과에서는 멀티프로세싱과 달리 실행 시간이 크게 줄지 않았다. 이 함수는 외부 응답을 기다리지 않고 파이썬 계산을 계속한다. GIL이 활성화된 환경에서는 스레드가 여러 개여도 이 계산을 여러 코어에서 동시에 실행하지 못한다.

## 마무리

계산이 오래 걸린다면 멀티프로세싱을 먼저 검토하고 파일이나 네트워크 응답을 기다리는 시간이 길다면 멀티스레딩을 검토할 수 있다. 다만 작업을 나누고 결과를 모으는 비용이 있으므로 실제 데이터로 비교해야 한다.

작업자 수를 늘리는 것만으로 해결되지는 않는다. 프로세스는 메모리 사용량과 사용 가능한 CPU 코어 수를 보고 정한다. API 호출은 상대 서버의 동시 요청 제한도 함께 확인해야 한다.
