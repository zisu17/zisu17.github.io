## 실습 구성

로컬에서 Kafka를 실행하고 웹 UI로 토픽을 만들어보려고 한다. macOS에서 Lima로 Linux 가상 머신을 만들고 그 안에 Kafka와 Kafka UI를 실행하는 구성이다.

Kafka는 기존 실습과 같은 3.6.1과 ZooKeeper 구성을 기준으로 한다. 최신 Kafka 설치 안내가 아니므로 새 환경에서는 사용할 버전의 Java 요구 사항과 메타데이터 관리 방식을 먼저 확인한다.

Kafka 실행에 Spark나 Python은 필요하지 않다. Kafka 배포 파일의 `_2.12` 같은 표시는 해당 배포판의 Scala 버전이지 외부 Spark 환경과 반드시 맞춰야 하는 옵션은 아니다.

## Lima 가상 머신 준비

다음 명령은 macOS 터미널에서 실행한다.

```bash
brew install lima
limactl start --name=cdc-kafka-test template:ubuntu
limactl list
limactl shell cdc-kafka-test
```

이후 명령은 가상 머신 안에서 실행한다. VM에 Kafka를 내려받아 사용할 것이므로 호스트 홈 디렉터리 전체에 쓰기 권한을 줄 필요는 없다.

Ubuntu 환경에서 Java와 Docker Engine을 준비한다.

```bash
sudo apt update
sudo apt install -y openjdk-17-jre-headless docker.io curl
sudo systemctl start docker
java -version
```

Lima에 포함된 컨테이너 실행 환경과 별개로 이 예제에서는 Docker Engine을 사용한다. 이미 실행 중인 환경이 있다면 중복 설치와 포트 충돌 여부를 먼저 확인한다.

## Kafka 내려받기

오래된 릴리스는 Apache 보관소에서 받는다. 아래 명령에는 관리자 권한이 필요하지 않다.

```bash
curl -fLO https://archive.apache.org/dist/kafka/3.6.1/kafka_2.12-3.6.1.tgz
tar -xzf kafka_2.12-3.6.1.tgz
cd kafka_2.12-3.6.1
```

`config/server.properties`에서 아래 두 값을 설정한다. 같은 키가 이미 있다면 중복으로 추가하지 말고 기존 값을 수정한다.

```properties
listeners=PLAINTEXT://127.0.0.1:9092
advertised.listeners=PLAINTEXT://localhost:9092
```

이번 구성에서는 Kafka와 UI가 같은 Linux VM의 네트워크를 사용한다. 따라서 브로커가 알려주는 `localhost:9092`로 UI도 접근할 수 있다. 다른 VM이나 외부 클라이언트까지 연결하려면 그쪽에서 접근 가능한 주소와 네트워크 설정으로 바꾸어야 한다.

## ZooKeeper와 Kafka 실행

```bash
bin/zookeeper-server-start.sh -daemon config/zookeeper.properties
bin/kafka-server-start.sh -daemon config/server.properties

bin/kafka-topics.sh --list --bootstrap-server localhost:9092
```

브로커가 바로 준비되지 않았다면 실행 로그를 확인하고 다시 조회한다. 단순히 백그라운드로 실행했다는 이유만으로 정상 기동을 확인한 것은 아니다.

## Kafka UI 연결

Kafka UI는 브로커의 토픽과 메시지 등을 살펴볼 수 있는 별도 애플리케이션이다. 아래는 UI 이미지 태그를 고정한 실행 예시이다.

```bash
sudo docker run --rm --name kafka-ui --network host \
  -e SERVER_ADDRESS=127.0.0.1 \
  -e KAFKA_CLUSTERS_0_NAME=local \
  -e KAFKA_CLUSTERS_0_BOOTSTRAPSERVERS=localhost:9092 \
  provectuslabs/kafka-ui:v0.7.2
```

`--network host`는 **Linux VM 안의 Docker**를 기준으로 한다. UI 컨테이너가 VM의 네트워크를 함께 사용하므로 브로커의 `localhost:9092`에 연결할 수 있다. `-p`로 포트를 매핑하는 방식과는 다르다.

일반적인 Docker 브리지 네트워크에서 컨테이너의 `localhost`는 그 컨테이너 자신이다. Kafka를 호스트에서 실행하면서 UI만 컨테이너로 띄울 때 이 차이 때문에 연결에 실패하기 쉽다.

UI는 VM의 `127.0.0.1:8080`에서 수신한다. Lima의 기본 포트 포워딩이 동작하고 macOS의 8080 포트가 비어 있다면 호스트 브라우저의 `http://localhost:8080`에서 열 수 있다. 접속되지 않으면 VM 안에서 먼저 접근되는지와 Lima의 포워딩 설정을 확인한다.

이 UI 예제에는 사용자 인증을 추가하지 않았다. 로컬 실습용으로만 사용하고 인터넷에 공개하지 않는다.

## 마무리

UI가 실행되는 것과 Kafka에 연결되는 것은 별개이다. 연결이 안 될 때는 UI가 바라보는 주소와 브로커의 `advertised.listeners`를 함께 확인한다. 특히 VM과 컨테이너를 섞어 사용할 때는 각 환경의 `localhost`가 어디를 뜻하는지 먼저 구분하면 된다.

실습을 끝내면 UI를 실행한 터미널에서 `Ctrl+C`로 종료하고 Kafka와 ZooKeeper도 중지한다.

```bash
bin/kafka-server-stop.sh
bin/zookeeper-server-stop.sh
```
