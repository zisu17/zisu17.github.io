## 구글 애널리틱스 (Google Analytics)

예전에 전략기획팀 인턴으로 일하면서 Google Analytics로 회사 콘텐츠의 사용자 분석을 한 적이 있다. 개발자가 된 뒤에는 내 블로그에 방문자 분석 기능을 붙여보고 싶어 다시 사용하게 됐다.

단순 조회 카운터만으로는 몇 번 조회됐는지와 몇 명이 방문했는지를 구분하기 어렵다. GA4에서는 조회수와 사용자, 세션을 나누어 볼 수 있다. 다만 수집된 이벤트와 식별 정보를 기준으로 집계하므로 실제 사람 수와 정확히 같지는 않다. 광고 차단과 동의 설정, 여러 기기 사용 등에 따라서도 결과가 달라진다.

## Jekyll에 측정 ID 추가

내 블로그는 Jekyll로 만든 GitHub Pages 사이트이다. 설정 파일에서 측정 ID를 읽어 페이지에 Google 태그를 넣는 방식으로 연결한다. 아래 파일을 먼저 확인하고 공통 레이아웃에서 태그가 어디에 포함되는지 찾는다. 파일 이름과 설정 키는 테마 버전에 따라 다를 수 있다.

```text
zisu17.github.io
├── _config.yml
└── _includes
    └── analytics-providers
        └── google-gtag.html
```

**1. _config.yml 수정**
GA4를 사용하므로 이 테마의 provider를 `google-gtag`로 설정한다. 측정 ID는 테마가 실제로 읽는 키에 넣어야 한다. 아래는 `measurement_id`를 사용하는 설정 예시이며 오래된 테마에서는 `tracking_id` 같은 다른 이름을 사용할 수 있다.

```yaml
# Analytics
analytics:
  provider         : "google-gtag" # false (default), "google", "google-universal", "google-gtag", "custom"
  google:
    measurement_id    : "G-**********" # Replace this with your ID, or delete
```

**2. _includes/analytics.html 확인**
이 테마는 `analytics.html`에서 설정한 provider에 맞는 파일을 불러온다. GA4를 사용하므로 `google-gtag.html`을 확인한다.

```liquid
{% raw %}
{% if jekyll.environment == 'production' and site.analytics.provider and page.analytics != false %}

{% case site.analytics.provider %}
{% when "google" %}
  {% include /analytics-providers/google.html %}
{% when "google-universal" %}
  {% include /analytics-providers/google-universal.html %}
{% when "google-gtag" %}
  {% include /analytics-providers/google-gtag.html %}
{% when "custom" %}
  {% include /analytics-providers/custom.html %}
{% endcase %}

{% endif %}
{% endraw %}
```

**3. _includes/analytics-providers/google-gtag.html 수정**
웹 스트림의 태그 설치 안내에서 Google 태그를 확인한다. 기존 파일에 태그가 이미 있다면 측정 ID만 맞추고 스크립트를 한 벌 더 추가하지 않는다.

![Google 태그 설치 안내 화면](https://github.com/zisu17/zisu17/assets/108858121/cef77f4e-2228-4657-a3ed-eaa10d07f894)

```html
<!-- Google tag (gtag.js) -->
<script async src="https://www.googletagmanager.com/gtag/js?id=G-**********"></script>
<script>
  window.dataLayer = window.dataLayer || [];
  function gtag(){dataLayer.push(arguments);}
  gtag('js', new Date());

  gtag('config', 'G-**********');
</script>
```

**4. 공통 레이아웃의 태그 포함 위치 확인**

최종 HTML 한 페이지에는 같은 Google 태그가 한 번만 포함되도록 한다. 이 테마처럼 `scripts.html`이나 공통 레이아웃에서 이미 `analytics.html`을 호출하고 있다면 포스트 레이아웃에 또 추가할 필요가 없다. 아래는 포함 위치를 보여주는 예시이지 기존 호출에 더하라는 뜻은 아니다.

```liquid
{% raw %}
    {% include head.html %}
    {% include head/custom.html %}
    {% include analytics.html %}
{% endraw %}
```

**5. 빌드된 페이지에서 확인**

예시의 `analytics.html`은 `jekyll.environment == 'production'`일 때만 태그를 넣는다. 로컬에서 확인할 때는 `JEKYLL_ENV=production`으로 빌드해야 한다. 페이지 소스에서 태그와 측정 ID가 한 번만 설정되는지 확인한다. Google 태그를 두 번 넣으면 중복 수집이나 설정 충돌이 생길 수 있다.

## 수집 결과 확인

배포 후에는 실시간 보고서나 DebugView에서 방문 이벤트가 들어오는지 확인한다. 개발자 도구 Network 탭에서 Analytics 수집 요청도 확인할 수 있다. 일반 보고서는 처리 시간이 필요하므로 배포 직후 데이터가 없다는 이유만으로 설치 실패라고 판단하지 않는다.

같은 브라우저에서 글을 열고 새로고침해보면 페이지 조회 이벤트가 추가되는지 확인할 수 있다. 이때 조회수가 늘어났다고 새로운 방문자가 생긴 것은 아니다.

| 지표 | 의미 |
|---|---|
| 조회수 | 웹에서는 페이지 조회 이벤트가 발생한 횟수. 같은 페이지의 반복 조회도 포함 |
| 사용자 | 선택한 기간에 활동한 사용자를 식별해 집계한 값. 활성 사용자와 전체 사용자는 기준이 다름 |
| 세션 | 한 사용자의 방문을 일정 기준으로 묶은 단위. 기본적으로 30분간 활동이 없으면 종료 |

한 사람이 한 번 방문해 글 세 개를 읽었다면 조회수와 사용자 수는 다를 수 있다. 다시 방문하면 같은 사용자에게 새로운 세션이 생길 수도 있다. 숫자를 비교할 때는 기간과 지표 이름을 함께 확인해야 한다.

## 마무리

측정 ID를 발급받는 것과 실제로 이벤트가 수집되는 것은 별개이다. 배포된 HTML에서 Google 태그가 한 번만 실행되는지 확인하고 실시간 보고서에서 방문 이벤트가 들어오는지 확인하면 된다.
