## RabbitMQ 시작하기

RabbitMQ는 메시지를 받아 큐에 보관하고 Consumer에게 전달하는 메시지 브로커이다. 요청을 받은 애플리케이션이 모든 작업을 바로 처리하지 않고 다른 작업자에게 넘길 때 사용할 수 있다.

여기서는 macOS에 서버를 설치하고 관리 화면에 접속할 계정을 만들어보려고 한다. 관리 화면에 로그인하는 권한과 큐의 메시지를 읽고 쓰는 권한은 서로 다르므로 함께 확인한다.

## Homebrew로 설치하기

```bash
brew install rabbitmq
brew info rabbitmq
```

Homebrew는 필요한 Erlang 의존성도 설치한다. 설치되는 RabbitMQ 버전은 실행 시점에 따라 달라진다. 아래 화면은 2024년 실습 기록이다.

![Homebrew의 RabbitMQ 설치 결과](https://github.com/zisu17/TIL/assets/108858121/1c6dedb1-58a5-4d02-85cc-07a8aea4710d)

`rabbitmqctl` 같은 명령을 찾지 못한다면 `brew info rabbitmq`에서 설치 경로와 `sbin` 경로 안내를 확인한다. Homebrew 설치 위치는 Intel Mac과 Apple Silicon Mac에서 다를 수 있다.

## 서버 실행하기

서비스로 관리하려면 다음 명령을 사용한다.

```bash
brew services start rabbitmq
brew services list
rabbitmq-diagnostics ping
```

일반 사용자로 실행한 `brew services start`는 사용자 로그인 시 시작하도록 등록한다. 관리자 권한으로 시스템 부팅 시 등록하는 것과는 구분해야 한다.

![RabbitMQ 서비스가 시작된 상태](https://github.com/zisu17/TIL/assets/108858121/b5a3ed65-ef55-4855-abb9-4aa2951a07fb)

현재 터미널에서 로그를 보며 실행하려면 서비스 대신 `rabbitmq-server`를 사용할 수도 있다. 같은 노드를 두 번 실행하지 않도록 기존 서비스부터 중지한다.

```bash
brew services stop rabbitmq
rabbitmq-server
```

두 방식 중 하나만 선택한다. 이후 설정 명령은 서버가 실행 중인 상태에서 사용한다.

## 관리 화면 활성화

```bash
rabbitmq-plugins enable rabbitmq_management
```

플러그인이 활성화되면 `http://localhost:15672/`에서 관리 화면을 열 수 있다. 일반적인 AMQP 연결 포트인 5672와 관리 화면의 15672는 용도가 다르다.

![RabbitMQ 관리 화면의 로그인 페이지](https://github.com/zisu17/TIL/assets/108858121/3d3c9c43-a676-4bdc-9617-23fd363fce17)

초기 설정에서 생성되는 `guest` 계정은 기본적으로 로컬 접속으로 제한된다. 외부 접속을 위해 이 제한부터 풀기보다는 별도 계정과 필요한 권한을 만든다. 계정을 만들더라도 네트워크 접근과 TLS 설정이 자동으로 해결되지는 않는다.

![로컬 guest 계정으로 접속한 관리 화면](https://github.com/zisu17/TIL/assets/108858121/1c0bef1a-da3a-493f-97ec-8d6546c02b0f)

## 관리자 계정 만들기

아래 명령은 대화형 터미널에서 비밀번호를 입력받는다. 비밀번호를 명령문에 직접 적으면 셸 기록 등에 남을 수 있으므로 피한다.

```bash
rabbitmqctl add_user blog-admin
rabbitmqctl set_user_tags blog-admin administrator
rabbitmqctl list_users
```

사용 중인 구버전에서 비밀번호 입력을 지원하지 않으면 해당 버전의 CLI 사용법을 먼저 확인한다. 예제의 간단한 계정명을 쓰더라도 비밀번호는 충분히 길고 추측하기 어렵게 정한다.

`administrator` 태그는 사용자와 가상 호스트 등을 관리하는 권한이다. 이것만으로 모든 큐에 메시지를 쓰거나 읽을 수 있는 것은 아니다.

## 가상 호스트 권한 설정

가상 호스트(vhost)는 큐와 Exchange 같은 자원을 나누어 관리하는 영역이다. 여기서는 실습용 `/blog`를 만들고 이 영역에만 접근 권한을 준다.

```bash
rabbitmqctl add_vhost /blog
rabbitmqctl set_permissions -p /blog blog-admin ".*" ".*" ".*"
rabbitmqctl list_permissions -p /blog
```

`set_permissions` 뒤의 세 값은 순서대로 자원 구성과 쓰기, 읽기를 허용할 이름 패턴이다. 예제의 `.*`는 `/blog` 안의 모든 해당 자원을 허용한다. 실제 애플리케이션 계정에는 필요한 이름과 작업만 허용하고 관리자 계정을 그대로 사용하지 않는 편이 좋다.

새 계정으로 관리 화면에 로그인한 뒤 `/blog` 가상 호스트가 보이는지 확인한다. 메시지 클라이언트에서도 같은 가상 호스트를 지정해야 한다.

![관리자 계정으로 접속한 RabbitMQ 화면](https://github.com/zisu17/TIL/assets/108858121/af109cbf-9870-4600-87db-2c9728b8ee79)

위 화면은 당시 계정으로 확인한 기록이므로 예제의 계정명과는 다를 수 있다.

## 마무리

RabbitMQ 계정은 로그인할 수 있는지와 어떤 가상 호스트의 자원을 사용할 수 있는지를 나누어 확인해야 한다. 접속 오류가 나면 사용자 인증과 vhost 권한, 클라이언트가 지정한 vhost를 차례로 확인한다.

실습 서비스가 필요 없으면 `brew services stop rabbitmq`로 중지한다. 더 이상 쓰지 않는 실습 계정은 연결과 사용처를 확인한 뒤 `rabbitmqctl delete_user blog-admin`으로 삭제할 수 있다.
